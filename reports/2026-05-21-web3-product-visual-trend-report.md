# Web3 竞品产品与视觉趋势日报 - 2026-05-21

> 时间范围说明：优先覆盖 2026-05-20 ~ 2026-05-21 的公开信息；若单日信息不足，补充近 7 天内的官方页面/公告，并在条目中标注。

## 今日核心判断

- **视觉风格变化结论（相对上一期）**：头部竞品的“产品化运营模块”进一步从“步骤与卡片”演进到“**等级/徽章/排行榜 + 市场/目录化（Marketplace/Catalog）**”两套更具系统性的表达：前者把资格与信任视觉化（badge/level/score），后者把 AI/策略/工具包装成可检索、可安装、可复用的“模块商品”。
- **产品逻辑变化结论（相对上一期）**：从“点数化/资格化 + 产品使用”继续升级为“**资格化 + 声誉化（Trader Level/Badge） + 可插件化能力供给（Skills Marketplace）**”。增长不再只靠一次性任务，而是把参与行为沉淀为可展示的等级与可组合的能力栈。
- **对 MEXC 的一句话建议**：把「任务/点数」升级为可长期复用的「等级与声誉」体系，并同步建设“可组合能力货架”（策略模板/工具模块/玩法组件）；视觉上以“徽章 + 下一档解锁 + 排行/进度 + 模块目录”作为新的增长主视觉骨架。

## 相对上一期变化

- **新增趋势**
  - **“等级/徽章”开始成为转化入口的一部分**：不止点数资格，还把“表现/可信度”做成可视资产（profile badge、列表露出），用于提升跟随/订阅/参与转化（Bybit）。
  - **AI/工具开始出现“目录化/商店化”的稳定形态**：从单一活动页叙事，进入可持续运营的“技能市场/能力库”（OKX）。
  - **B2B/开发者向的“稳定币发行能力”走到台前**：不再只谈交易所产品，而是把基础设施包装成可对外售卖的能力（Coinbase Custom Stablecoins）。
- **强化趋势**
  - **任务机制更偏“成长框架”**：从“做任务拿奖励”强化为“按周期更新的排行榜/分段赛季 + 任务抽奖”的组合（Bybit Boost Battle、KuCoin Futures Competition）。
  - **可信表达继续加强**：规则、资格、计算口径、时间轴、限制条件更完整，页面更接近“产品说明书/活动操作台”，弱化纯海报型夸张措辞。
- **减弱趋势**
  - 纯“奖池数字 + 炫光金币”仍存在，但在关键转化页面的主叙事里权重继续下降；更多变成“排行榜机制中的一个参数”，而不是唯一卖点。
- **反转或需要修正的判断**
  - 无（今天的新增信号更多是对上一期“点数化/产品化页面”的延伸升级，而非否定）。
- **持续观察但尚未确认的信号**
  - Binance Wallet 的 Alpha Task Points 是否会从“特定活动”继续扩展为跨产品、跨场景的统一等级/权益体系（目前更像阶段性强运营抓手，仍需后续跟踪）。

## 视觉风格变化

- **色彩与质感**
  - 强促销炫光仍存在，但“关键转化页”继续偏向低噪音、可信表达：更少金属炫彩、更多中性底色 + 局部强调色。
- **KV 和版式结构**
  - KV 仍承担“入口情绪”，但转化区已稳定为“模块化信息架构”：时间轴、任务卡、资格卡、规则/FAQ、风险提示。
- **高频视觉元素**
  - 徽章（badge）、等级（level）、排行榜（leaderboard）、进度与解锁（progress/unlock）、分类标签（category tag）、评分/安全标识（score/safety）。
- **标题层级和利益点表达**
  - 从“奖金最大化”转向“机制清晰化”：把“怎么赚、凭什么拿、差多少”作为主利益点结构，而不是只放奖池数字。
- **品牌资产使用方式**
  - 更像“产品组件库”：同一套卡片/标签/徽章规范跨活动复用，降低每次活动从零设计的成本，也提升用户识别与理解速度。

## 产品逻辑变化

- **主推产品方向**
  - Copy Trading/策略类强调“可信与转化资产”（等级徽章）。
  - AI/工具类从“活动页叙事”走向“能力货架/技能市场”。
  - 收益/借贷类强调“资金效率”而非单一 APR 口号。
- **用户转化路径**
  - 从“看见奖池 → 参与”进一步转向“看懂规则与资格 → 完成任务/积累等级 → 获得权益并持续复用”。
- **激励机制**
  - 排行榜 + 周期赛制 + 任务抽奖成为高频组合；同时把“等级/徽章”作为长期激励而不仅是奖励发放。
- **活动机制**
  - 更强调“注册后计入/滚动窗口/分段赛季/资格限制”这类可控规则，体现风控与公平性叙事。
- **功能包装方式**
  - 工具/AI 的包装趋向“模块商品化”：可搜索、可版本、可安装、可评估，形成长期运营的供给体系。

## 视觉变化与产品逻辑变化的关系

- 当增长目标从“短期刺激”转向“长期参与与信任”时，视觉必须提供**可解释性**：资格如何获得、等级为何上升、奖励如何结算。
- 当激励骨架变成“等级/徽章/排行榜”时，视觉的关键不是炫酷，而是**状态感与比较感**：你在第几档、与谁相比、下一档差多少、解锁什么权益。
- 当工具/AI 走向“技能市场”时，视觉自然迁移到“目录/商店”语言：分类、搜索、版本、评分与安全提示，帮助用户做选择并降低风险感知。

## MEXC 可跟进方向（5 条可执行建议）

1. **把点数体系升级为“等级与声誉体系”**：将用户行为沉淀为可展示资产（badge/level），并绑定权益与推荐位；输出统一的徽章与等级视觉规范（颜色、层级、形态、命名）。
2. **建立“玩法模块库”而不是每次活动重做**：把任务卡、资格卡、时间轴、排行榜、抽奖、乘数说明、风险提示做成组件化模板，平面与产品共用一套结构语言。
3. **为 Bot/策略类产品规划“策略货架”雏形**：哪怕先从站内策略模板目录开始，也要具备分类/标签/风险级别/适用人群/一键启用入口，逐步逼近“可检索的能力供给”。
4. **Earn/借贷的核心视觉从“收益数字”改为“资金路径”**：统一用资金流向图、清算/抵押率提示、期限与流动性标签建立可信表达，降低高收益带来的不信任。
5. **把“下一步解锁”做成默认叙事**：所有活动/任务中心默认展示“当前状态 → 下一档目标 → 可得权益”，减少用户理解成本，提高连续参与率。

## 风险与不建议跟进方向

- **不建议把差异化押在奖池数字**：行业模板化严重，用户对“数字刺激”耐受提升，投入产出比继续下降。
- **不建议做“黑箱点数/黑箱等级”**：一旦用户无法理解积分/等级如何计算，转化会被不信任吞噬；设计必须为规则可解释性服务。
- **不建议把 AI 做成纯赛博概念视觉**：当行业开始用“安全评分/版本/下载量/调用量”建立可信度时，空泛概念会显得廉价且可能引发反感。
