# Web3 友商产品功能与活动视觉分析日报 - 2026-05-19

面向：平面设计部门主管  
范围：Binance / OKX / Bybit（产品功能页、活动页、官媒线索入口）

## 今日重点判断

1. **“收益 + 活动上新 + Web3 钱包/生态 + 自动化工具”仍是三家共同的产品包装主轴**：从本次采集目标页的功能栏目选择可见，三家都把增长最直接的模块放在一级入口（Earn/理财、Launchpool/Launchpad、Web3 Wallet/Web3、Trading Bot、Promotions/Campaigns）。这意味着视觉与文案策略大概率继续围绕“立刻可理解的收益/福利 + 低门槛参与动作”组织。
2. **活动中心（Promotions/Campaigns/Activity）被当作“持续上新货架”而非单页事件**：对设计团队来说，KV 不应只追求单次爆点，更关键是“可批量生产、可快速换肤、在同一框架下保持品牌一致”的活动组件体系（模块化标题层级、机制卡片、奖励模块、CTA 组合）。
3. **同质化风险集中在：霓虹渐变/3D 元素堆叠 + 过度金融化语言 + 机制信息隐藏太深**：当竞争对手持续聚焦这些一级模块时，视觉层面更容易走向同一种“Web3 科技炫彩风”。MEXC 如果继续跟随，会在活动海量迭代中迅速失去辨识度；需要用“更清晰的信息架构 + 更强的品牌符号化元素”来对冲。

> 重要说明：今日采集到的 12 个核心产品/活动页面均返回失败状态（未能获取标题、层级结构、CTA 文案、KV 图片与截图）。本报告仅能基于“对手重点入口的栏目选择 + 官媒入口线索”做结构性判断，并给出可落地的设计策略建议；不做具体单页 KV 复刻评审。

## 友商产品功能包装动态（从“一级入口选题”反推）

### Binance
- **Earn（理财收益）**：把“收益型产品”作为稳定转化入口，通常需要“清晰的收益表达 + 风险/门槛信息可视化”的页面结构支撑。
- **Launchpool（上新挖矿/活动）**：将“新币上新”作为强刺激活动位，常见卖点为“参与步骤少、时间窗口明确、奖励可视化”。
- **Web3 Wallet（Web3 钱包）**：体现其对“自托管/链上生态”入口的长期投入，包装往往强调“安全、便捷、跨链/多链、探索生态”。
- **Activity（活动中心）**：作为持续活动货架，需要强信息架构与统一活动组件。

### OKX
- **Web3（Web3 钱包/DEX/NFT）**：以“Web3 超级入口”打包多条业务线，设计需要“多能力一屏可扫”的信息层级（钱包/交易/NFT/发现）。
- **Earn（理财收益）**：同样将收益作为基础入口，设计常强调“收益率、期限、风险等级、推荐组合”。
- **Trading Bot（交易机器人）**：强调“自动化/策略化、降低操作难度”，适合用“策略卡片 + 结果预期 + 风险提示”的结构表达。
- **Campaigns（活动中心）**：与 Binance 类似，走“持续上新货架化”。

### Bybit
- **Earn（理财收益）**：稳定转化入口。
- **Launchpad（上新/Launchpad）**：与 Launchpool 同型，强调“参与资格/额度/时间窗口/奖励结算”。
- **Trading Bot（交易机器人）**：强调“策略模板/一键运行/数据背书”。
- **Promo（活动中心）**：活动货架化入口。

## 活动视觉与转化打法观察（适用于活动中心与功能页的通用推断）

虽然未能获取当日页面截图，但基于这类一级模块的长期稳定形态，三家常见的“转化骨架”对我们仍有参考价值：

- **首屏**：一句主标题（利益点）+ 关键数字/标签（限时/新手/高 APY/零门槛）+ 主 CTA（立即参与/开始赚取/一键开启）+ 次 CTA（了解规则/查看教程）。
- **机制区**：用 3–5 张信息卡解决“我能得什么、要做什么、什么时候结束、门槛是什么、风险是什么”。
- **奖励/权益区**：将奖励拆成“可直接领/累计领取/阶梯任务”三个组件，避免把规则藏在长文里。
- **信任区**：用“背书与安全感”收尾（常见为品牌实力/风控/资产安全提示/FAQ），降低犹豫成本。

对设计的要求不在“更炫”，而在“更快读懂 + 更容易做出行动”。

## 对 MEXC 设计团队的机会点（可借鉴但不抄样式）

1. **建立“活动货架组件系统”**：统一活动 Banner/KV、标签（限时/新手/返佣/上新）、奖励模块（金额/比例/积分）、CTA 组合（主次按钮 + 规则链接）的规范，使活动中心高频上新仍保持品牌一致。
2. **把“机制信息”视觉化前置**：首屏下方即给出“3 步参与/时间轴/门槛卡”，减少用户滚动与跳转；用图标+短句替代长段落。
3. **收益与风险的“双通道表达”**：收益用大数字 + 小注释（口径、条件），风险/限制用对比色小组件常驻（避免后置到 FAQ 才出现），减少投诉与负面传播风险。
4. **Web3 入口做“任务化探索”而非“功能堆叠”**：当对手把 Web3 打包为超级入口时，MEXC 可用“场景任务”（存入/跨链/兑换/赚取/探索）组织视觉层级，让新用户更容易选路。
5. **强化品牌识别而非跟随霓虹风**：保留 Web3 科技感可以，但建议锁定一套“品牌符号 + 形状语言 + 插画/3D 主角体系”的可持续资产库，避免每次活动都换一种“公版炫彩”。

## 风险与不建议跟进方向

- **不建议只跟随“渐变霓虹 + 3D 金币/星球 + 光束”**：短期像“Web3”，长期会变成“谁都像谁”，且在活动中心密集露出时更显杂乱。
- **不建议把规则压缩成一行小字**：活动越复杂，越需要机制卡片与时间轴；否则转化靠误导，后续客服与舆情成本更高。
- **不建议首屏堆叠过多卖点**：收益、上新、返佣、空投同时强调会稀释主 CTA；应坚持“一页一个主动作”。
